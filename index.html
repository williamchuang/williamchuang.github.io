I construct an attention mechanism that natively lives on hyperbolic geometry and uses automorphic (Maass-type) kernels. A critical-entropy controller (CEAS) regulates the inverse temperature so that attention entropy hovers near a pseudo-critical point.

Within this setting, the classic Langlands triad is realized inside a neural operator: automorphic ⟷ Galois ⟷ motive.

Overview

I design at the intersection of geometry, control, and security. My recent work treats attention temperature β as a controllable parameter rather than a constant; derives safe corridors from thermodynamic arguments; and refactors trained models into finite operators with certified wrappers so that targeted changes don’t require retraining. On the security side, I explore cryptomorphically equivalent model families: weight‑distinct networks that provably preserve I/O behavior under symmetry‑preserving transforms.

Three pillars

1) Efficiency (CEAS)

Treat attention scaling as β (inverse temperature). Do an early, budgeted search, fix β (or clamp it within a corridor), and monitor entropy/energy metrics. Results: faster steps‑to‑target on controlled tasks and improved numerical behavior.

2) Interpretability (Finite‑Machine Lift)

Lift a trained model’s closed‑loop behavior to a finite operator P = D + N (cycles + transients). Use cycle projectors to trace reasoning flows, detect degeneracy, and perform edit‑without‑retrain with certificates.

3) Security (GRAIL)

Run models over algebraically encrypted representations (research direction). Explore cryptomorphic twins: weight‑distinct yet function‑equivalent models for per‑tenant deployments and tamper‑resistance.

Featured frameworks

CEAS — Critical Entropy Attention System

  • What: β‑control for attention (inverse temperature).
  • Why: The fixed 1/√dk heuristic is an initialization convenience; after learning begins, variance assumptions drift.
  • How: Short n‑ary search early in training → choose β* → lock or clamp in a corridor; monitor with entropy/energy metrics.
  • Artifacts: derivations (thermo/KL/RG), corridor algorithm, small‑task demos, and safety clamps (log‑sum‑exp, bounds).

DFA / Finite‑Lift — Decompose for traceability

  • What: Determinize rollout → lift to P → split P = D + N → build cycle projectors.
  • Why: Produce symbolic traces and stable subspaces for safe, local edits.
  • How: Runtime sentinels (O(1) membership), systole/holonomy monitors, and certificates reporting coverage/time/memory.

GRAIL — Geometry‑native secure execution (research)

  • What: Algebraic/geometry‑native encodings intended to keep parameters/activations opaque to untrusted CPUs.
  • Why: Explore trustless execution paths outside TEEs and without FHE‑class slowdowns.
  • Status: Theory + prototypes; seeking independent benchmarking and review. Performance claims are workload‑dependent and provided with caveats.
  • Twin models: Generate cryptomorphic variants (weight‑distinct, function‑equivalent) for per‑user instances and anti‑fingerprinting.

Λ‑Stack — The integrated system

CEAS (β‑control) + finite lift (trace) + GRAIL + optional dual‑lock security (GRAIL plus MSIA) = an interpretable, hardened transformer. Designed to be edit‑ready and auditable.

Evidence & claims — how to read

  • Claims are scoped: Where I cite “orders‑of‑magnitude vs FHE,” this is a research target under representative workloads; not a blanket guarantee. I actively seek third‑party measurement.
  • Certificates: For safety/edits I provide corridor bands, Lipschitz‑style deviation bounds, and coverage/time/memory reports for verification.
  • Demos: Small tasks (e.g., reversal) show β‑search → steps‑to‑target reductions and stable high‑β regimes. Scaling studies are in progress.

Selected results (concise)

  • Early β‑search works: on controlled tasks, a brief early search (log‑grid, 5–10 points) reliably finds a stable high‑β regime; fixing β then reduces steps‑to‑target vs. 1/√dk.
  • Edit‑without‑retrain: finite‑lift + cycle shims enable local logic changes with bounded deviation on a protected manifold.
  • Cryptomorphic twins (research): construct weight‑distinct, function‑equivalent variants via symmetry‑preserving transforms; useful for per‑tenant deployments.
